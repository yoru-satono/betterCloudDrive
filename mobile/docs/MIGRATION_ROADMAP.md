# KMP 移动端迁移路线

> 状态：临时工作稿。本文仅用于当前迁移讨论，不属于正式产品文档或长期事实来源，不应从 README、架构、开发、参考或正式 Roadmap 文档链接。路线确认或失效后应更新、归档或删除本文。

本文面向移动端产品、开发和验收人员，定义从旧 `android/` 应用迁移到 `mobile/` KMP 应用的阶段边界、依赖关系和完成门槛。本文只规划交付范围，不规定类、接口、依赖库或具体实现方案；每个阶段在开始前另行编写一份可执行的详细 Plan。

规划基线日期为 2026-08-22。Android 是当前唯一交付平台，iOS 只保留公共代码和编译能力，不实现 iOS 宿主或平台服务，不支持桌面端。

## 重新划分的原因

历史阶段 1 同时规划了应用外壳、安全会话、网络、数据库、可恢复传输、Android 后台执行、界面和完整测试，实施范围过大。最终交付验证了重要基础能力，但用户可见范围仍只有登录、个人根目录和传输队列，而且真实下载断点续传、通知更新限流和 Android 9 设备回归尚未闭环。

因此，阶段 1 在本路线中定性为“生产基础原型”，不再视作生产基础层或旧 Android 业务迁移已经完成。后续阶段采用纵向切片：每个阶段只解决一个主要业务域或一条主要用户旅程，完成后交付可运行、可验收的 Android 增量。

## 阶段规模约束

每份阶段 Plan 必须遵守以下边界：

- 只包含一个主要业务域或一条主要用户旅程，通常不超过 1～3 个主要页面。
- 不同时承担大规模基础设施建设和多个产品业务域。
- 明确列出范围外事项，不能用“先搭基本框架”代替阶段交付。
- 完成后必须有可运行的 Android 构建和至少一条真实后端端到端验收流程。
- 公共代码和界面继续保持 iOS 目标可编译；只有阶段明确授权时才能增加平台实现。
- 默认复用现有后端协议。如果发现后端能力缺失，应先建立独立的后端前置 Plan，而不是隐含扩大客户端阶段。
- 未达到验收门槛的能力保留为当前阶段阻塞，不得宣称完成后转移到下一阶段。
- 从阶段 5 起，新增或修改的用户可见文本必须进入共享国际化资源，不得继续产生硬编码的中文或英文界面文本。

多个阶段可以进入同一个版本迭代，但每个阶段仍使用独立 Plan、独立验收记录和独立完成判断。

## 固定产品与平台边界

- 迁移期间保留旧 `android/` 应用，作为行为参考和回滚方案；阶段 22 前不删除、不替换。
- 不迁移旧 Android 的本地令牌、偏好、缓存或传输记录。
- 移动端 OnlyOffice 维持强制只读。启用移动编辑需要另立产品、技术和商业许可项目。
- Android 不实现 Web 端的全局后台管理功能，团队管理范围遵循现有 Android 管理范围决策。
- 权限、资源状态和异步任务结果以后端为事实来源，客户端只消费有效权限和语义错误。
- Android 每阶段均验证 Debug、Release/R8；涉及平台能力时覆盖对应 Android 版本。

## 里程碑 A：基础能力收口

### 阶段 2：传输可靠性收口

状态：已于 2026-08-22 完成。Android 9 WorkManager 与 Android 14 UIDT 的自动化和 64 MiB 真实后端旅程均通过。

范围：关闭当前传输实现已经暴露的可靠性缺口，包括真实流式下载和 Range 恢复、通知更新限流，以及 Android 9 WorkManager 分支的设备验收。

完成门槛：上传和下载在断网、暂停、进程终止和重新启动后能够继续；Android 9 与 Android 14 的后台路径均通过设备验收；日志中不再出现应用触发的通知投递限流。

范围外：导航、目录管理、新业务页面和团队 UI。

### 阶段 3：产品应用外壳

状态：已于 2026-08-22 完成。Android 9 与 Android 14 导航设备测试、完整默认 Docker 栈、可观测性基线和 API 34 真实用户旅程均通过。

范围：建立正式的顶层导航、页面结构以及统一的加载、空状态、错误和重试体验；Debug 诊断能力与正式产品页面隔离。

完成门槛：登录后进入稳定的产品外壳，个人空间、传输、团队入口和个人设置具有明确导航位置；阶段 1 的单个长列表不再承担全部界面。

范围外：完整文件管理、团队业务和账号扩展流程。

## 里程碑 B：个人空间日常可用

状态：已于 2026-08-25 达成。阶段 4～8 的浏览、国际化、文件管理、可恢复传输、搜索与只读预览均通过自动化和真实后端旅程。

### 阶段 4：个人文件浏览

状态：已于 2026-08-22 完成。Android 9 与 Android 14 设备测试、105 文件三页真实后端旅程、完整默认 Docker 栈和可观测性验收均通过。

范围：目录层级、面包屑、刷新、分页、排序、列表/网格和文件详情。

完成门槛：用户可以从根目录进入任意层级目录、返回上级或指定面包屑位置，并稳定查看大目录和文件元数据。

### 阶段 5：国际化基础收口

状态：已于 2026-08-23 完成并通过资源结构复验。默认英语、CN/SG 简体目录使用同名稳定键，硬编码与资源完整性门禁、Android 13+ 系统语言声明、真实资源回退、界面和通知已在 Android 9/API 28 与 Android 14/API 34 上通过设备验收。

范围：建立 KMP 共享国际化资源体系，将阶段 0～4 已有的界面、无障碍描述、稳定错误提示和 Android 通知迁移为可本地化资源；首批完整支持简体中文与英语，并根据系统语言自动选择。

完成门槛：两种语言下登录、个人文件浏览、传输、我的和诊断流程均不存在混合语言或缺失资源；切换系统语言后应用界面、错误和通知正确更新；生产代码不再硬编码用户可见的中文或英文文本，后续阶段具备可持续复用的资源和测试规范。

范围外：应用内语言选择、语言偏好跨设备同步和新增第三种语言；这些能力进入阶段 9。

### 阶段 6：个人文件管理

状态：已于 2026-08-25 完成。后端契约和 141 项黑盒测试、KMP 主机与国际化门禁、Android 9/API 28 与 Android 14/API 34 设备矩阵、完整默认 Docker 栈和可观测性基线均通过；API 34 真实用户旅程验证了三级目录管理、SAF 上传后的移动、递归复制、冲突反馈、批量删除和强制停止后的状态一致性。

范围：新建文件夹、重命名、移动、复制、选择和删除。

完成门槛：旧 Android 中常用的个人文件修改行为可以在 KMP 应用完成，失败和冲突具有可解释反馈。

### 阶段 7：个人传输体验

状态：已于 2026-08-25 完成。API 34 的 64 MiB 联合旅程验证了单批 UIDT、暂停/继续、断网、强制停止后复用上传会话、缺失分片补传、非零 Range 下载、MD5 一致及终态任务、临时文件、URI/WAL、通知和系统任务清理；API 28/34 自动化均通过。

范围：上传到当前目录、多文件入队、下载到用户目标、独立传输队列以及前后台状态展示。

完成门槛：传输能力融入实际目录工作流，不再局限于个人根目录探针；队列可以查看、暂停、继续、取消和重试。

### 阶段 8：个人预览与搜索

状态：已于 2026-08-25 完成。API 34 真实旅程验证了不少于 105 个结果的三页搜索、导航恢复、PNG/SVG、空文本、512 KiB 截断文本、Media3 Range 与 Activity 重建，以及个人 OnlyOffice 只读和无商业许可警告；全部自动化与完整 Docker 栈门槛通过。

范围：图片、文本、视频和个人 OnlyOffice 只读预览；个人文件全局搜索、打开文件和打开所在位置。

完成门槛：用户可以搜索并查看主要文件类型，OnlyOffice 保持只读且不出现商业许可警告。

完成阶段 8 后，KMP 应用达到“个人空间日常可用”里程碑。

## 里程碑 C：个人功能对等

### 阶段 9：账号与个人设置

状态：已于 2026-08-27 完成。API 28/34 设备矩阵、SG 简体注册与邮件、精确地区同步、资料与容量、主题持久化、服务器切换清理和密码重置真实旅程均通过；Web/Tauri 兼容、完整 Docker 栈、黑盒与可观测性门槛通过。

范围：注册、验证码、找回和重置密码、个人资料、容量信息、应用内语言选择及偏好同步、主题和服务器管理。

完成门槛：账号生命周期和个人偏好不再依赖旧 Android 应用。

### 阶段 10：个人收藏与标签

状态：已于 2026-08-28 完成。API 28/34 设备矩阵、105 个个人项目的收藏与标签三页真实后端旅程、团队内容隔离、原子标签替换、Web/Tauri 兼容、完整 Docker 栈、黑盒与可观测性门槛均通过。

范围：收藏列表、添加和移除收藏、标签管理、文件标签分配和标签文件列表。

完成门槛：旧 Android 的个人内容整理流程在 KMP 中完整可用。

### 阶段 11：个人分享

状态：已于 2026-08-28 完成。API 28/34 设备矩阵、105 个个人分享的三页真实后端旅程、个人/团队隔离、密码与限制生命周期、公开访问和取消失效均通过；Web/Tauri 兼容、完整 Docker 栈、黑盒与可观测性门槛通过。

范围：分享创建、查看、编辑、密码显示、限制管理、复制链接和取消。

完成门槛：个人分享从创建到撤销的完整生命周期可用，并与后端状态一致。

### 阶段 12：个人回收站与版本

范围：回收站查看、恢复、永久删除和清空；文件版本查看、恢复、下载和删除。

完成门槛：个人文件恢复和历史版本能力达到旧 Android 对等。

阶段 9～12 可以在阶段 8 完成后按产品优先级调整顺序，但不得合并为一个阶段。完成阶段 12 后，个人空间基本达到旧 Android 功能对等。

## 里程碑 D：团队日常协作

### 阶段 13：团队工作区与只读浏览

范围：团队列表、团队创建、工作区切换、团队目录浏览、搜索、普通预览和 OnlyOffice 只读预览。

完成门槛：已有团队成员可以稳定进入团队、浏览目录并查看内容；没有写权限时不出现写操作。

### 阶段 14：团队文件协作

范围：权限允许时的新建、重命名、移动、删除、上传、下载和团队传输队列。

完成门槛：团队文件写入流程完整可用，界面行为严格遵循后端返回的有效权限。

### 阶段 15：团队成员与文件权限

范围：成员列表、添加和移除成员、角色调整、文件有效权限展示和权限管理。

完成门槛：Owner、Admin、Editor 和 Viewer 的可见操作、成员管理和文件权限行为与旧 Android 一致。

### 阶段 16：团队邀请与通知

范围：邀请创建、重发和取消；邀请深链接受和拒绝；通知列表、已读状态和关联页面跳转。

完成门槛：未登录和已登录用户都能从邀请链接完成正确流程，通知可以打开对应团队上下文。

完成阶段 16 后，KMP 应用达到“团队日常协作可用”里程碑。

## 里程碑 E：团队功能对等

### 阶段 17：团队收藏与标签

范围：团队收藏、团队标签、文件标签分配和标签文件列表。

完成门槛：团队内容整理能力达到旧 Android 对等。

### 阶段 18：团队分享

范围：团队分享创建、查看、编辑、密码、限制、统计、链接复制和取消。

完成门槛：团队分享管理完整可用，并正确执行团队分享权限。

### 阶段 19：团队回收站与版本

范围：团队文件恢复、永久删除和清空；团队文件版本查看、恢复、下载和删除。

完成门槛：团队恢复和历史版本能力达到旧 Android 对等。

### 阶段 20：团队管理

范围：团队改名、退出、删除、所有权转让和对应权限控制。

完成门槛：团队生命周期管理达到旧 Android 对等，破坏性操作具有明确确认和结果反馈。

### 阶段 21：审计与任务中心

范围：团队审计日志、筛选和导出；异步任务查看、重试和结果下载。

完成门槛：旧 Android 中的团队治理功能迁移完成。全局后台管理功能仍不进入移动端范围。

阶段 17～19 相互依赖较少，可以在阶段 16 完成后调整顺序，但每项保持独立 Plan。完成阶段 21 后，KMP 应用达到本路线定义的旧 Android 业务功能对等。

## 里程碑 F：迁移收口

### 阶段 22：发布与切换

范围：执行完整旧 Android 行为矩阵、稳定性和长时间运行回归、签名与升级验证、发布说明、监控和回滚方案，并评估旧应用停止维护或下线。

完成门槛：阶段 0～21 的验收证据完整；KMP 应用满足发布要求；旧应用的处置具有明确决策和可执行回滚路径。

范围外：旧 Android 本地数据迁移、iOS 发布和移动端 OnlyOffice 编辑。

“代码存在”“接口已经封装”“页面可以打开”都不能单独视作里程碑完成；完成判断以真实用户流程和验收证据为准。

## 每份详细 Plan 的固定结构

后续为具体阶段编写 Plan 时统一包含：

1. 阶段目标和用户价值。
2. 明确的范围、范围外事项和前置依赖。
3. 需要迁移的用户流程和与旧 Android 的行为对照。
4. 公共能力、Android 平台能力和后端协议的责任边界。
5. 自动化测试、设备测试和真实后端验收标准。
6. 文档、兼容、回滚和阶段完成条件。

详细 Plan 不应提前纳入后续阶段的页面或业务能力。发现范围膨胀时，应拆出新的前置或后续阶段，而不是继续扩大当前 Plan。
