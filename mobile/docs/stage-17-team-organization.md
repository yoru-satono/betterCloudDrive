# 阶段 17：团队收藏与标签

阶段 17 将团队收藏、团队标签、标签文件列表和文件标签分配迁移到 KMP 移动端。应用版本为 `versionCode=18`、`versionName=0.18.0-stage17`。Android 是当前已有设备验证的应用壳；业务 API、Repository、Store、路由和界面状态位于共享源码，继续为后续 iOS 应用复用。

## 用户能力

- 团队工作区顶栏“整理”菜单可进入团队收藏和标签，不增加新的顶层导航项。
- 收藏列表和标签文件列表每页 50 项，支持 300 ms 搜索防抖、刷新、继续加载、打开所在位置、文件夹导航、预览和下载。
- 文件更多菜单打开时才读取收藏状态，目录列表不会逐项发请求；收藏增删使用当前用户在当前团队内的独立状态。
- 所有团队成员可浏览标签。OWNER/ADMIN 可以创建、编辑和删除团队标签；EDITOR/VIEWER 不显示这些管理入口。
- 只有目标文件的有效权限包含 `canWrite` 时才显示标签分配入口。编辑器一次处理一个项目，保存使用单次原子替换；OWNER/ADMIN 还可在编辑器中创建并选中新标签。

## 协议与一致性

新增团队文件标签读取和原子替换端点：

```text
GET /api/v1/teams/{teamId}/files/{fileId}/tags
PUT /api/v1/teams/{teamId}/files/{fileId}/tags
```

PUT 请求体为 `{ "tagIds": [1, 2] }`。服务端先去重并验证全部标签归属，再删除旧关联和写入新关联；空数组清空标签。目标文件不可写、任一标签不属于当前团队或事务失败时，不修改原有关联。Web/Tauri 标签编辑也切换到同一原子端点，避免多请求部分成功。

团队收藏固定按收藏创建时间、文件 ID 降序，标签文件按关联创建时间、文件 ID 降序。列表先过滤当前用户不可读的项目再分页。标签名称去除首尾空白，颜色规范化为小写 `#rrggbb`，同团队重名返回稳定冲突。

## 状态与权限边界

`TeamFavoritesStore` 和 `TeamTagsStore` 都显式绑定 `teamId`。团队切换会取消旧请求并清空列表、分页、收藏状态和编辑器；退出、会话失效和切换服务器通过 `AppCoordinator` 重置。个人和团队整理使用不同 API/Repository/Store，不能相互泄漏。

标签 CRUD 使用团队成员管理权限，即 OWNER/ADMIN。标签列表要求团队成员身份；标签文件列表只返回当前用户可读项目；读取单文件标签要求有效读取权限，替换、附加和移除要求有效写权限。客户端隐藏不可用操作只是体验优化，服务端仍执行最终授权。

## 验证范围

- 后端单元测试覆盖团队标签规范化、稳定冲突、有效权限、去重替换、审计和非法跨团队标签写入前失败。
- Web API 契约验证 GET/PUT 原子路径，团队文件页不再逐标签查询和逐条修改。
- KMP MockEngine 契约验证请求路径与 JSON；Store 测试覆盖防抖、分页去重、按需收藏状态、角色门禁、原子保存、团队切换和重置。
- Android Compose 设备测试覆盖团队“整理”入口以及 OWNER/ADMIN 与 EDITOR/VIEWER 的标签管理可见性。
- 真实 API 旅程建立 105 个团队项目，验证收藏和标签文件三页分页、名称与颜色规范化、标签原子替换、去重、清空和文件仍可访问。
- `mobile-unit` 继续包含 Android Debug/Release 和 `:shared:compileIosMainKotlinMetadata`；后者只代表 iOS 共享源码编译边界，不代表 iOS 应用或平台测试。

旧版 `android/` 只用于核对迁移行为，本阶段不修改、不构建也不测试它。
