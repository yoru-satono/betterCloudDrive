# 阶段 13：团队工作区与只读浏览

## 交付范围

阶段 13 将 KMP 团队占位页替换为可用的只读工作区，应用版本为 `versionCode=14`、`versionName=0.14.0-stage13`。

- 团队入口按名称和 ID 稳定分页，支持刷新、创建团队和工作区切换。
- 团队目录每页 50 项，在读取权限过滤后分页；支持三级目录、面包屑、名称/修改时间/大小排序、列表/网格和只读详情。
- 团队全局搜索采用 300 ms 防抖、50 条分页、ID 去重和尾部重试，可进入文件夹或打开所在位置。
- 图片、视频使用短期团队 ticket 流式预览；文本只读取前 512 KiB；OnlyOffice 固定请求后端签发的 `mobile=true` 只读配置。
- 所有团队角色在本阶段都不显示上传、下载、重命名、移动、删除、分享、收藏、标签、版本或权限操作，也不创建团队传输任务。

## 架构与安全边界

`TeamWorkspaceApi/Repository` 只负责团队列表、创建、详情、目录、元数据和搜索，`TeamPreviewApi/Repository` 只负责 ticket、认证文本 Range 和 Office 配置。`TeamsStore`、`TeamBrowserStore`、`TeamSearchStore`、`TeamPreviewStore` 分别拥有自己的状态、作业、缓存和 `reset()`；它们不读取或修改个人 Store。

团队路由只携带团队和文件的稳定 ID。媒体 ticket 仅保存在当前预览 Store 内存中，缓存键同时包含团队 ID 与文件 ID，不写入路由、Room、DataStore、日志或无障碍文本。切换团队、离开预览、退出登录、切换服务器或会话失效都会清除相应状态。进程被终止后不会恢复选中团队，账号恢复仍从个人根目录开始。

后端团队列表固定按 `name ASC, id ASC`；目录固定文件夹优先，并按请求字段、名称和 ID 稳定排序。目录和搜索均在权限过滤后分页，搜索会修剪关键词，空查询不执行全团队扫描。Web/Tauri 的现有团队编辑链路不变。

- 后端团队目录与搜索专项测试 44 项通过；完整后端、Testcontainers 集成、Web/Tauri、148 项黑盒、Prometheus 规则和 7 项可观测性验收通过。黑盒首次运行出现一次连接层瞬时非法响应头，单项连续复跑 5 次及完整套件复跑均通过，未通过放宽断言规避。
- KMP 团队网络契约和四个 Store 的主机测试通过；国际化门禁、Debug、Release/R8 和 iOS 公共元数据编译通过。API 28 的 28 项设备测试全部通过，API 34 的 29 项中 28 项通过，唯一跳过项是只适用于 API 33 及以下的 WorkManager 路径。
- API 34 真实旅程加载了 106 个团队和 105 个同前缀团队项目，覆盖三页稳定分页、应用内创建团队、三级目录、排序、列表/网格、搜索、打开所在位置及进程重启后回到个人根目录。团队浏览和预览结束后 Room 的 `transfer_tasks` 仍为 0。
