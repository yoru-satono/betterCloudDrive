# 阶段 16：团队邀请与通知

## 交付范围

阶段 16 补齐团队邀请和站内通知闭环，应用版本为 `versionCode=17`、`versionName=0.17.0-stage16`。

- 团队成员页面提供“成员 / 邀请”双标签；OWNER 可邀请 ADMIN、EDITOR、VIEWER，ADMIN 只能邀请 EDITOR、VIEWER。
- 邀请支持稳定分页、创建、重发和幂等取消。重复创建会刷新同团队同邮箱的待处理邀请，过期邀请可重发并恢复为待处理状态。
- 邮件继续打开 canonical Web 邀请页，用户可显式选择“在移动端打开”，跳转严格限定的 Android 自定义深链。
- 未登录用户可查看邀请并续接登录或锁定邀请邮箱的注册；已登录账号邮箱不匹配时只能切换账号，不能接受或拒绝。
- 产品外壳提供通知铃铛、`99+` 上限徽标、分页筛选、单条/全部已读和白名单内部导航。
- 登录且应用处于前台时建立 SSE；进入后台、退出、换服务器或会话失效后立即关闭。

## 架构与安全边界

邀请使用独立的 `TeamInvitesApi/Repository/Store` 与 `IncomingInviteStore`。公开邀请详情请求不携带 Bearer Token；接受和拒绝继续使用统一认证、单飞刷新和最多一次重放。邀请 token 是 Store 私有字段，不进入 `StateFlow`、类型安全路由、Room、DataStore、日志或报告。Activity 重建仍复用 Application 内 Store；进程被彻底终止后必须重新打开邀请链接。

通知使用独立的 `NotificationsApi/Repository/Store`。API 在受控 SSE 作用域中申请并消费一次性 ticket，Store 只接收未读数事件；重连使用 1、2、5、10、30 秒上限退避。页面展示由服务端稳定消息键和参数驱动，现有 14 类通知均映射为本地化资源，未知键只显示通用通知，不显示原始语义键。

通知链接仅允许团队邀请、团队根目录/文件夹和成员设置。非法、无权限或移动端未支持的目标不会作为外部 URL 打开。点击通知时，已读写入与合法目标导航相互独立：已读失败会保留未读状态和提示，但不阻止导航。

后端邀请变更在事务中锁定团队或邀请行；接受与拒绝按相同最终状态保持幂等。邀请 token URL 段和 SSE ticket 查询参数在审计与访问日志中脱敏。Web 中转按钮由用户主动点击，不自动拉起应用，也不自动改变移动端服务器地址。
