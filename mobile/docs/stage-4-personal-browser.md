# 阶段 4 个人文件浏览

## 范围

阶段 4 将个人空间从根目录列表扩展为日常可用的只读文件浏览器，应用版本为 `5 / 0.5.0-stage4`。本阶段不提供重命名、移动、删除、搜索、预览、团队浏览、子目录上传或多文件传输，也不修改 Room schema 和传输引擎。

## 架构与行为

- 根目录和文件夹使用 Navigation Compose 可序列化类型安全路由；文件夹系统返回键回到父目录，点击已选中的“个人”入口直接回到根目录。
- 已知文件夹点击时直接追加面包屑；Activity 路由恢复时通过文件元数据接口逐级重建祖先，并检测路径循环、非文件夹目标和失效权限。
- 每个当前面包屑分支保留独立的目录内容、分页和首个可见文件 ID。离开该分支时释放无关快照，强制停止后恢复会话仍从根目录开始。
- 目录每页 50 条，接近末尾自动加载。分页请求按文件 ID 去重，加载更多失败只显示尾部重试，刷新失败保留已有内容。
- 排序支持名称、修改时间和大小的升降序。切换排序时重新加载第一页；失败则原子恢复旧排序、内容和缓存。列表与网格切换不发网络请求。
- 普通文件点击后刷新元数据。手机使用 Material 3 底部页，宽度不小于 600dp 时使用详情侧栏，展示名称、MIME、大小、创建/修改时间、MD5、版本数和单文件下载。
- 只有根目录显示“上传到个人根目录”，子目录不显示上传入口。

## 后端契约

`GET /api/v1/files` 现在实际应用 `sortBy=fileName|updatedAt|fileSize` 与 `order=asc|desc`。返回顺序固定为文件夹优先、请求字段和方向、名称升序、ID 升序；修改时间为空时排在同组末尾。未知参数分别回退名称和升序，保证旧客户端兼容。

## 测试与验收

自动测试覆盖后端排序白名单、稳定次级排序、非法参数回退和跨三页顺序；KMP 主机测试覆盖请求参数、元数据解析、路径重建、分页去重、尾部重试、刷新保留内容、排序回滚和目录缓存；Compose 设备测试覆盖三级目录、面包屑、返回、列表/网格、手机底部详情与宽屏详情栏。

阶段完成门槛为：后端、集成、黑盒、移动主机测试均通过；API 28 与 API 34 设备测试通过；Debug、Release/R8 和 iOS 公共代码元数据编译通过；完整默认 Docker 栈及可观测性验证通过。

## 验收结果

阶段 4 已于 2026-08-22 完成验收：

- 后端单元测试和 Testcontainers 集成测试通过；黑盒测试 `140 passed, 20 deselected`，包含超过两页的个人文件稳定排序用例。
- `mobile-unit` 通过，覆盖 KMP 主机测试、Debug、Release/R8、Release lint 和 iOS 公共代码元数据编译。
- `bcd_api28` 的 Android 9/API 28 设备测试全部通过；`bcd_api34` 的 Android 14/API 34 设备测试通过，API 34 上仅按设计跳过 WorkManager 专属用例。
- API 34 真实后端旅程准备了三级目录和 105 个实际可下载文件，连续加载到第三页后显示 `共 105 项`；名称、修改时间、大小排序契约与升降序由后端和设备测试共同验证。
- 真实旅程完成列表/网格切换、手机详情底页、单文件下载、传输完成状态以及强制停止后的会话恢复；重新启动后进入个人根目录。
- 完整默认 Docker 栈全部健康，可观测性测试 `7 passed, 153 deselected`；测试期间临时放宽的请求限流已恢复为默认值。
- API 34 Logcat 未发现应用崩溃、ANR、`Package enqueue rate` 或 `Shedding`。
