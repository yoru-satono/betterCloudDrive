# 阶段 7：个人传输体验

## 交付范围

本阶段把阶段 1～2 的可恢复传输能力正式接入个人文件浏览器。所有个人目录均可通过 Android 系统文件选择器一次选择多个文件；URI 去重后最多接受前 100 项，不可读项和超限项分别统计。上传目标冻结为打开选择器时所在的目录，任务持久化并成功提交后台批次后页面仍停留在原目录，通过反馈提供“查看传输”操作。

普通文件的更多菜单和详情页均可发起单文件下载。文件夹上传、批量下载、并行传输、团队传输、预览和搜索仍不在本阶段范围内。应用版本为 `versionCode=8`、`versionName=0.8.0-stage7`；后端协议、Room schema、旧 Android 应用和 iOS 平台实现均未修改。

## 批次与恢复模型

- 一次用户操作生成唯一批次 ID，系统调度参数只包含最多 100 个任务 ID及上传、下载剩余字节估算；任务真实参数继续从 Room 读取。
- Android 14+ 在 Activity 可见时提交一个 UIDT Job，Android 13 及以下提交一个带网络约束的前台 WorkManager Worker。
- 批次执行器按任务创建顺序调用公共 `TransferEngine`，全局互斥继续保证同一时间最多传输一个文件。
- 永久失败、暂停或取消当前项后继续下一项；`429`、`5xx` 和临时网络错误保留当前任务，由系统指数退避后重试该批次。
- Activity 启动时核对系统任务和 Room；未被系统批次覆盖的排队任务按每批最多 100 项重新提交，中断中的准备或运行任务先恢复为排队。
- 调度失败会把相关任务标记为可重试失败，并使用稳定错误键 `error.backgroundScheduling`。

## 文件权限和目录刷新

上传成功或取消后释放不再被其他任务引用的 SAF 读取权限；下载成功或取消后释放写入权限。失败、暂停和等待登录任务保留权限，以支持继续或重试。用户确认“清除已结束任务”后删除成功、失败和取消记录，同时删除失败下载 `.part`、尽力取消遗留上传会话并释放不再需要的 URI 权限。活跃、暂停和等待登录任务不会被清除。

上传成功会使目标目录缓存失效。当用户仍停留在该目录时，控制器等待该目录不再存在排队、准备或运行中的上传，再按原已加载页数统一刷新一次，并尽量保留滚动锚点；批量中的每个文件完成时不会分别请求目录。

## 传输页面

传输页按上传和下载分为两个可恢复标签，并显示各自任务数量。活跃及排队任务按创建时间升序排列，成功、失败和取消任务按更新时间倒序排列。任务卡片展示方向、文件名、状态、已传输/总字节、百分比、进度条和本地化错误，继续提供暂停、恢复、取消与失败重试。

顶层传输入口显示未结束任务数量徽标。终态任务存在时可打开清除确认框；说明文字明确失败任务清除后不能直接重试。新增页面文本、通知、反馈和无障碍文本都使用默认英语、CN 简体和 SG 简体的同键资源。

## 验收记录

阶段 7 已于 2026-08-25 完成自动化与 API 34 真实旅程验收：

- 在三级目录一次选择零字节、小文件和确定性 64 MiB 文件，只生成一个 UIDT 批次和一条活动通知；JobScheduler 确认任务以获批的用户发起任务运行。
- 64 MiB 上传在暂停、继续、断网和强制停止后保留同一上传会话。中断时已完成 8/13 个 5 MiB 分片，重启后仅补传 5 个缺失分片，最终 MD5 为 `f84e578f43748504942c1af84bf63d9a`。
- 同一文件下载在 `.part` 已写入 360440 字节后恢复，后端记录 `206` 和 `Range: bytes=360440-`，最终文件大小与 MD5 均与源文件一致。
- 清除终态任务后，Room 终态记录、`.part`、通知、UIDT Job 和测试 URI 授权均为零。验收期间发现 SQLite WAL 可能保留已删除 URI，现已在删除后截断 WAL 并压缩数据库，API 28/34 设备测试均验证数据库文件不再包含该句柄。
- 应用过滤后的 Logcat 未发现崩溃、ANR、重复执行、通知限流，也未发现 Token、ticket、正文或本地 URI 泄漏。
- `mobile-unit`、API 28/34 `mobile-android`、141 项 `blackbox` 和 7 项 `observability` 全部通过；Debug、Release/R8、国际化门禁和 iOS 公共代码元数据编译通过，完整 14 服务 Docker 栈健康。
