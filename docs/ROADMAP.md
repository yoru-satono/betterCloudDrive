# BetterCloudDrive 后续计划

本文档只记录尚未完成的工作，按安全性、数据正确性、可扩展性和产品收益排序。任务完成后应从本文档移除，并由 Git 历史、测试和发布说明保留实施记录。

## P0 安全与数据正确性

### TEAM-01 收紧团队任务权限

- 状态：待完成。
- 目标：阻止普通成员查看或重试无权操作的团队任务。
- 规则：
  - `OWNER`、`ADMIN` 可以查看和重试团队全部任务。
  - 普通成员只能查看自己创建且当前仍有目标资源权限的任务。
  - `AUDIT_EXPORT` 仅允许 `OWNER`、`ADMIN` 创建、查看、重试和下载。
  - `FOLDER_ZIP` 允许发起人在仍有目标文件读取权限时查看、重试和下载。
  - `ONLYOFFICE_SAVE` 仅允许目标文件当前可写成员或团队管理员重试。
  - `THUMBNAIL`、清理等系统任务仅允许 `OWNER`、`ADMIN` 手工重试。
- 实现要求：授权逻辑放在 Service 层；任务列表按当前用户权限过滤，不能只按 `teamId` 查询。
- 验收：补齐 Service、Controller 和契约测试，覆盖 Viewer 拒绝、发起人权限撤销、跨用户任务和不同任务类型。

### TASK-01 原子领取后台任务

- 状态：待完成。
- 目标：避免多个 scheduler 实例重复处理同一个团队任务。
- 实现要求：
  - 使用 PostgreSQL `FOR UPDATE SKIP LOCKED` 在同一事务内领取任务并将其从 `PENDING` 更新为 `RUNNING`。
  - worker 只处理成功领取的任务，不再先查询再单独调用 `markRunning`。
  - 为长时间停留在 `RUNNING` 的任务增加可配置超时和恢复策略。
  - 保留上传完成、OnlyOffice callback 和结果写入的业务幂等保护。
- 验收：并发集成测试证明两个 worker 不会领取同一任务；进程异常退出后的超时任务可以恢复。

- 实现要求：支持状态/类型筛选、分页、结果下载和按权限重试；继续遵守 Android 不承载全局 Admin 团队后台的决策。

### NOTIFY-01 改造实时通知认证

- 状态：待完成。
- 目标：SSE URL 不再携带完整 access token，并为 Android 实时刷新提供安全接口基础。
- 实现要求：
  - 新增 Bearer Token 保护的 stream ticket 接口，签发短期、用户绑定、一次性票据。
  - EventSource 只携带 stream ticket；后端停止接受 `accessToken` 查询参数。
  - Web/Tauri 完成切换后，再为 Android 接入 SSE 或等价的前台实时刷新机制。
- 验收：访问日志和 EventSource URL 中不出现 access token；票据过期、重复使用和跨用户使用均被拒绝。

## P1 异步架构演进

### QUEUE-01 团队后台任务接入 Redis Streams

- 状态：待完成。
- 前置：`TASK-01` 已完成。
- 目标：降低轮询延迟并支持可靠的多实例任务处理。
- 实现要求：
  - `team_tasks` 继续作为事实来源，创建任务的事务只写数据库。
  - Outbox publisher 向 `bcd:stream:team-tasks` 投递唤醒事件。
  - consumer 收到消息后调用原子 claim，不直接依赖消息负载决定任务状态。
  - 依次迁移审计导出、缩略图、文件夹 ZIP 和 OnlyOffice 保存。
  - 保留低频数据库扫描作为漏消息兜底，并监控 pending、claim、耗时、重复投递和超时恢复。
- 验收：重复消息不会重复生成结果；Redis 短暂不可用后任务仍可通过数据库兜底完成。
