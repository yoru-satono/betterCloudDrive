# BetterCloudDrive 后续计划

本文档只记录尚未完成的工作，按安全性、数据正确性、可扩展性和产品收益排序。任务完成后应从本文档移除，并由 Git 历史、测试和发布说明保留实施记录。

## P0 生产上线阻断

- 让 `R__development_data.sql` 只在开发/测试环境生效，或从生产构建产物移除，并增加生产库不存在默认 `chain`、`admin` 账号的自动检查。

## P1 生产可靠性

- 将 PostgreSQL、对象存储和密钥的一致性备份、加密、异地复制、保留清理和失败告警自动化，并持续记录恢复演练的实际 RPO/RTO。
- 发布不可变且可追溯的应用镜像，建立从开始保留生产数据后的版本化 Flyway 增量迁移和兼容性验证流程。
- 接入受控密钥管理，评估 JWT、分享密码和 OnlyOffice 所需的双版本或可审计重加密能力。

## P2 产品与运维增强

以下事项在出现明确产品或生产升级需求后再排期：

- 自定义团队角色、权限模板或用户组。
- 支持权限位逐层合并，而不是最近覆盖整体替换。
- 评估 Owner 权限是否允许受组织策略约束。
- 超大目录 ZIP、版本保留数和任务结果保留时间的管理界面。
- 团队 Owner 自助申请或管理配额。

P0 在任何公网生产部署前必须完成。P1 在承诺生产恢复目标前完成并通过演练；P2 按真实产品和部署需求独立排期。

旧数据库资料不要求迁移，项目不建设历史版本增量升级链。当前支持的依赖与运行时版本见[文档索引中的版本基线](README.md#当前版本基线)。
