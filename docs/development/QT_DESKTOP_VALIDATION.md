# Windows Qt 桌面迁移前验证

历史原型报告，仅描述 2026-11-21 的验证范围。当前客户端使用 Qt Multimedia 独立播放器；开发操作见 [Qt 桌面开发](../../desktop/README.md)，当前状态见[功能矩阵与正式模块验收](QT_DESKTOP_ACCEPTANCE.md)。以下原型阻塞项与打包结果不作为当前版本的放行结论。

验证日期：2026-11-21。项目基线：`e153f07`。范围为独立 PySide6 + Qt WebEngine 原型；当前正式桌面客户端仍为 Tauri。本轮不执行 Linux 验证。

## 结论

真实 Vue、认证、断点传输和 OnlyOffice 可以在 Qt 原型中工作。当前预编译 Qt WebEngine 无法解码本轮 H.264/AAC MP4 样本；在保持该媒体能力的要求下，正式替换仍有阻塞项。

原型和复现命令见[实验工程](../../experiments/qt-desktop/README.md)。这份报告描述验证证据，不宣布完整桌面功能已迁移。

- Windows 11 IoT Enterprise LTSC，build 26100，x86_64。
- uv 独立 CPython 3.12.13；PySide6 6.12.0，WebEngine/PDF wheel 6.12.0.140，PyInstaller 6.22.3。传递依赖以实验目录 `uv.lock` 为准。

- 普通应用来源为 `127.0.0.1:5184`；诊断 CDP 显式启用且仅绑定回环地址。桥接位于隔离 JS world，外部 iframe 不获取原生对象。
- Token、refresh token、代理密码及邮件验证码不写入报告。测试结束删除浏览器存储和缓存；账号保留审计，运行内文件和团队按 ID 清理。

## 工程发现

1. Windows 高频 JSON 原子替换受到文件共享锁影响，导致偶发 `PermissionError`。原型改用 SQLite 事务保存队列与设置，修复后重复通过传输和重启恢复检查。
2. 宿主 PATH 中 Poppler 的 `icuuc.dll` 被 PyInstaller 错误采集，造成打包版 QtCore 加载失败。构建脚本隔离 DLL 搜索路径后，产物可独立启动；没有手工修改生成目录中的 DLL。
3. Qt 不支持 Playwright 初始化所用的部分 Browser context 命令。验证驱动改为页面级 CDP，保留真实窗口与真实网络请求。
4. PDF 插件文本不在主页面 CDP AX 树中。验证同时检查 PDF 子帧、稳定截图中的白纸与正文像素，并保存截图进行视觉复核，拒绝空白加载占位。
5. OnlyOffice 的 iframe 和 canvas 出现早于文档 ready。测试通过真实 ready/state 事件、关闭引导浮层、实际键盘输入及后端版本和文档内容共同判断保存结果；API 轮询为 3 秒，避免高频轮询触发限流。
6. 本机强制 renderer accessibility 的诊断参数会干扰 PDF 插件渲染，已移除该参数。最终源码和打包版均重新检查稳定截图，视觉复核确认显示完整的 `Qt PDF validation` 文本。

## 性能与分发

同机、相同窗口尺寸，分别执行五次独立进程启动和十秒空闲采样，使用全新浏览器 Profile，未清理 OS 文件缓存。指标是进程树 RSS，包含共享页重复统计，不等于独占物理内存。它是工程参考，不是严格实验室性能结论。

最终对照运行：`benchmark-fcd431113b`，两个客户端各五次均成功。

| 指标 | 当前 Tauri | Qt 原型 |
| --- | ---: | ---: |
| 启动到登录页中位数 | 0.546 s | 0.985 s |
| 空闲进程树 RSS 中位数 | 454.3 MiB | 388.3 MiB |
| 本机分发文件 | 主程序 14.7 MiB，另依赖 WebView2 | 完整目录 570.6 MiB |

原始数据保留在忽略版本控制的 `test-results/qt-desktop/benchmark-fcd431113b/results.json`。当前结果支持“Qt 原型启动较慢、进程树 RSS 较低、分发目录较大”，不能外推成所有平台或生产负载的性能结论。

分发大小必须区分 Qt 整个目录与 Tauri 主程序。Tauri 的系统 WebView2 是额外共享依赖，不能把主程序体积当作含运行时的完整安装体积。
