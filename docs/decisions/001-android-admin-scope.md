# ADR-001：Android 全局管理范围

- 状态：已接受
- 日期：2026-07-03
- 适用范围：Android、Web/Tauri 管理端、全局管理员接口

## 背景与约束

Better Cloud Drive 同时包含团队内管理和跨团队的全局平台管理。全局管理涉及归档、恢复、彻底清理、配额覆盖、跨团队成员/文件检查、系统日志和死信等高风险操作，需要密集表格、过滤、上下文确认和可审查状态。

Android 手机布局适合成员日常操作，但在核心团队工作流尚需持续验证时，同时复制完整全局管理台会扩大高风险交互面和维护成本。

## 决策

Android 不实现完整的全局管理员控制台。全局用户、团队、系统日志、死信和跨团队管理保留在 Web/Tauri；Android 聚焦普通用户及其所属团队内、由服务端权限允许的工作流。

Android 继续支持团队文件、成员、邀请、分享、标签、收藏、回收站、审计查看/导出、通知、权限和文档预览编辑。团队 OWNER/ADMIN 可以在所属团队内使用已有管理能力，但这不等同于 `ROLE_ADMIN` 的平台管理面。

## 考虑过的替代方案

- 完整复制 Web 管理台：功能对称，但手机端高风险操作的上下文和批量审查体验不足，重复实现成本高。
- Android 完全不提供团队管理：风险最低，但会妨碍成员、邀请和团队文件等合理移动场景。
- 仅嵌入响应式 Web 管理台：减少原生开发，但认证、导航、文件交互和确认体验不稳定，仍不能消除误操作风险。

## 后果

- 正面：平台管理只有一个主要交互实现；高风险动作集中在更适合审查的 Web/Tauri 界面。
- 正面：Android 可以优先保证成员工作流、状态转换和端到端场景。
- 负面：管理员不能仅用 Android 完成全部平台运维。
- 负面：能力矩阵必须明确区分“所属团队管理”和“全局平台管理”。

如果以后确有移动全局管理需求，应作为独立 admin 模块重新评审，从只读团队列表/详情开始，并为归档、恢复、清理和配额变更设置独立确认及专项端到端测试。
