# ADR-004：元数据与文件内容分离存储

- 状态：已接受
- 日期：2026-08-20（对既有实现的追认记录）
- 适用范围：PostgreSQL、S3 兼容对象存储、Redis、备份恢复

## 背景与约束

云盘需要同时处理关系查询与大对象传输。用户、团队、目录树、权限、分享、版本、任务和审计适合事务性关系模型；文件正文、缩略图、历史版本和 ZIP 结果体积大，适合流式读取与 S3 生命周期。

数据库和对象存储不能参与同一个本地事务，因此设计必须明确权威状态、对象路径、失败补偿和恢复集，而不能假设一次请求会原子提交所有资源。

## 决策

PostgreSQL 保存对象的身份、归属、目录关系、权限、状态和对象路径；S3 兼容存储保存文件正文、缩略图、历史版本和部分任务产物。两者共同构成不可缺少的业务恢复状态。

Redis 只保存上传位图、ticket、锁、限流和计数等短期或可重建状态。RabbitMQ 只负责异步投递。OnlyOffice 卷不是文档历史版本的权威来源。

对象存储接口由 `betterclouddrive-storage` 封装，业务层只通过稳定的存储服务操作对象。跨资源写入使用幂等会话、持久任务、唯一约束和后续清理处理部分失败。

## 考虑过的替代方案

- 文件正文存入 PostgreSQL 大字段：事务直观，但数据库备份、复制、膨胀和大文件流量压力更高。
- 所有元数据交给对象存储：缺少关系查询、事务、权限和审计所需能力。
- 把 Redis 当作持久事实源：性能高，但不适合关键关系状态和独立恢复要求。
- 依赖 OnlyOffice 卷保存版本：Document Server 是编辑组件，不是 Better Cloud Drive 的版本事实来源。

## 后果

- 正面：关系查询与大对象传输分别使用适合的存储，可替换为其他 S3 兼容服务。
- 正面：对象路径、版本和任务状态可通过数据库查询与审计。
- 负面：必须处理对象成功而数据库失败、数据库成功而清理失败等不一致窗口。
- 负面：只备份 PostgreSQL 或只备份对象存储都无法完整恢复。

备份、迁移和灾难恢复必须把 PostgreSQL、对象存储及解密密钥绑定为同一恢复集。对象清理应由可重试任务执行，不能通过无边界 volume 清理代替业务生命周期。
